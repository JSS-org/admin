# JSS 健身业务系统 · 规划索引

> 本目录是项目的**权威规划文档**。合同正文与附件一/二/三（位于 `target/健身房合同_三附件签署稿/`）是范围与验收的最高依据，本目录不得与之冲突。

## 5 分钟上手

1. 读根目录 `AGENTS.md`（项目定位、当前阶段、目录地图、开发约定）。
2. 读本文件，了解文档地图与阅读顺序。
3. 读 `01-status.md`，掌握现状与资产盘点。
4. 需要做需求/排期时读 `02-scope.md` 与 `04-roadmap.md`。
5. 需要动架构/建表/接设备时读 `03-architecture.md` 与 `05-decisions.md`。

## 文档地图

| 文档 | 作用 | 何时读 |
| --- | --- | --- |
| `README.md`（本文件） | 索引、阅读顺序、文档维护约定 | 首次进入 |
| `01-status.md` | 项目现状、技术栈、资产盘点、旧规划失效点、里程碑进度 | 每次开工前 |
| `02-scope.md` | 合同 R01–R43 × 端 × 承载模块 × 现状矩阵；明确排除项 | 排期、需求确认、验收 |
| `03-architecture.md` | yudao 全栈技术路线：模块选型、账号体系、数据权限、IoT、支付/核销、通知 | 架构与详细设计 |
| `04-roadmap.md` | 里程碑（A/B/C）与敏捷迭代、提交/分支/验收证据计划 | 排期与迭代管理 |
| `05-decisions.md` | 待确认决策（ADR）与已定决策、影响面 | 做技术选型时 |

## 维护约定

- 动态进度只更新 `01-status.md`；范围变化只更新 `02-scope.md`；架构变化只更新 `03-architecture.md`；排期变化只更新 `04-roadmap.md`；每个决策在 `05-decisions.md` 记录编号与状态。
- 合同范围变化（新增/删除 R 项）必须同步 `02-scope.md`，并在 `05-decisions.md` 记录是否已签补充协议。
- 文档中所有“已实现 / 已完成”的表述必须有可复现证据；未接入的第三方能力一律标注“未接入”。
