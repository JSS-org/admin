## 4. 旧规划失效点

1. **后端选型**：旧规划为“自研 Go + pgx + 自建会话/权限 + 自研后台任务”，现改为 yudao（Spring Boot 全家桶）。`04-backend-design.md` 整篇失效。
2. **开发顺序**：旧顺序是“先前端 + Mock + PostgreSQL，再 Go”。现顺序是“先落地 yudao 基座 + gym 模块 + 管理端，再移动端”。原型的页面资产仍在，但不再是主线交付路径。
3. **数据库**：旧设计为 PostgreSQL 125 表；yudao 官方生态以 MySQL 为主（待确认）。
4. **范围口径**：旧 `requirements.md` 含大量运营功能（优惠券发放、积分、礼品码、批量消息、操课、临期筛选、展示素材、潜客跟进等）。**新合同附件一明确将这些排除**，只保留 R01–R43。原型中已实现的超范围功能不得再投入（处置见 D-03）。
5. **账号模型**：旧设计把“账号/员工/角色/门店”混在一张自定义模型里；现需按 yudao 的 `system_user`（B 端）+ `member_user`（C 端）重构，见 `03-architecture.md` 第 3 节。
