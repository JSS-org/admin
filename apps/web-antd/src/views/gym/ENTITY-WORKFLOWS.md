# 实体工作流整理

## 主入口与关联资料

| 实体 | 当前入口与处理 |
| --- | --- |
| 门店 | 门店资料 → 详情，统一查看封面、介绍、特色、地址地图、坐标、营业时间、联系方式、环境媒体和本店员工；媒体在详情内维护。 |
| 员工 | 员工资料 → 编辑，统一保存基本资料、所属门店与工资模板指定，展示各店模板版本和生效历史；网页账号、授权继续作为员工行操作。员工薪资关联、门店工资表隐藏菜单，保留兼容路由。 |
| 会员 | 会员详情汇集会员卡、私教权益、体测、课程预约和优惠券，关联数据按会员过滤、分页和权限加载；全店运营列表保留，支持跨会员查询。 |
| 课程 | 课程安排增加预约名单；课程产品、排课、预约、消课分别对应可售项目、具体场次、报名及已履约事实，保留运营入口。 |
| 优惠券 | 优惠券额度管理合并门店额度、批量维护、额度流水，后两者不再独占菜单；模板、发券批次、会员券仍对应不同生命周期。 |
| 合同与审批 | 合同模板和合同记录保留独立入口；恢复审批管理，集中查看开卡、签约、改价等审批。相关业务记录可直接发起申请，统一表单及附件规范；审批意见在详情内提交。 |
| 设备与器械 | 柜格配置、指令记录和远程操作归设备行；教学媒体归器械详情，保留设备与器械两种主实体。 |
| 积分与礼品码 | 积分规则、兑换商品、积分流水和礼品码批次保留，分别承担规则、库存和不可随意覆盖的历史记录；权益类型字段按条件展示。 |
| 财务与薪资 | 工资配置并入员工；薪资模板、收款账户、分账规则和分账明细保留，版本发布和财务确认仍使用专门业务操作。 |
| 活动、加盟与展示 | 活动封面和报名名单在活动详情维护；展示配置合并基础信息、媒体上传、区块编排和草稿预览。加盟管理和消息管理暂时隐藏菜单，保留兼容路由和权限。 |

## 批量编辑范围

批量选择限当前页；操作者先选择字段，再填写统一值。执行时逐项读取最新记录、检查可编辑状态并 PATCH，显示成功与失败数量。失败后保留原因，重试仅针对失败项；已成功项不会再次提交。当前不以空值清除批量字段，避免意外清空资料。

| 表格       | 可统一修改的字段 | 业务约束                         |
| ---------- | ---------------- | -------------------------------- |
| 门店       | 状态             | 门店写权限                       |
| 员工       | 职位、状态       | 员工写权限，服务端保护管理员账号 |
| 会员卡模板 | 售价             | 仅草稿                           |
| 操课产品   | 时长、价格       | 仅可编辑的团课产品               |
| 课程安排   | 场地、容量       | 仅待开课，容量受已有预约约束     |
| 设备       | 安装位置、状态   | 设备写权限                       |
| 器械       | 状态             | 器械写权限                       |
| 优惠券模板 | 总上限、每人上限 | 尚未分配额度                     |
| 积分规则   | 积分、每日上限   | 仅草稿                           |
| 积分商品   | 所需积分、库存   | 商品写权限及库存规则             |
| 活动       | 名额             | 服务端校验已报名人数             |
| 加盟咨询   | 跟进状态         | 加盟管理权限                     |

会员身份、账号授权、工资有效期、已发布规则以及订单、权益、流水和审核记录不开放通用批量覆盖；它们保留自己的授权、版本、确认或幂等操作。

## Drawer 表单约定

- 公共资源编辑抽屉和自定义抽屉均由 `.gym-dialog` 约束为全宽表单。规则使用纵向卡片，添加按钮位于循环外，即使规则为空也保留整行高度。
- 工资组成按销售提成、课时、固定加扣项显示比例/区间、单价或固定金额；分账比例以百分比输入并校验合计 100%；角色授权只对门店角色显示门店选择。
- 会员卡按期限/次数展示字段；优惠券按满减/折扣及门店范围展示字段；礼品码、积分商品按权益类型展示字段；积分规则仅在消费类型显示消费门槛。
- 发券和消息先选门店，再选本店会员，切换门店清空原会员；私信为单选会员，批量通知为多选。日期、时间、金额、比例和门店特色使用 DatePicker、TimePicker、InputNumber、百分比输入及标签选择。
- 合同、审批、设备、器械、发券、额度、消息、工资等自定义表单沿用完整标签和全宽布局；详情和操作结果表格保留水平滚动。

## 员工工资保存接口

`PATCH /admin/v1/employees/:id` 可同时附带 `storeAssignments` 与 `salaryAssignment: { storeId, templateId, effectiveFrom, effectiveTo }`。所属门店第一项为主门店，保留原门店的负责人标记和入店日期；移除仍有账号授权的门店会被拒绝。编辑普通员工资料不要求薪资权限；附带工资配置时另行检查 `payroll:templates` 总部权限。只允许已发布模板，模板及保存后的任职门店须覆盖目标期间。按月计算工资要求配置和模板覆盖整月，业务上应在月初切换。

保存先校验员工资料、所属门店和授权范围，再结束发生重叠的上一段工资配置并添加新段，保留历史。相同或倒序起始日期、冲突的未来计划、已确认工资使用期间等会被拒绝。新增配置失败时恢复旧期间、门店关联和审计记录，员工资料不产生部分写入。当前实现位于仓库内存 Mock；正式后端接入时必须用数据库事务实现相同原子语义。

## 验收范围

代码层面检查公共及业务 Drawer、菜单和实体入口；自动化覆盖条件字段提交、批量失败重试、12 类部分字段 PATCH 契约，以及员工与工资的联合保存、权限、日期冲突和回滚。补充了文件上传及下载、看板汇总、售卡和内容配置校验，以及门店切换时丢弃过期请求的测试。

已完成浏览器实测：门店详情及 390px 窄屏布局、详情中的本店员工、空工资规则的全宽添加按钮、规则类型切换、员工工资模板指定及保存后的生效历史、员工本页全选和批量编辑入口。

随后浏览器工具调用因使用额度耗尽被自动审批拒绝，提示 2026-09-15 02:08 恢复。因此新看板、用户名对齐、日期筛选、新菜单、媒体和 PDF 预览、售卡与展示配置，以及批量提交仍需浏览器复验；自动化通过不等于这些界面已完成视觉验收。详细记录见 `RELEASE-NOTES.md`。
